# DECISION_REQUEST Template(執行中 Owner 決策請求固定格式)

執行中(Step 3-6)浮現**真實取捨**時,照本 template 整理後再問 Owner。
**目的:Owner 只看整理過的決策請求**——不用自己從對話史拼湊上下文,
看完四段就能拍板。

## 什麼時候用(判準只有一個)

**不同解讀會不會導出完全不同的成果?**(CLAUDE.md 原則 1 的同一判準)

- 會(MVP vs full / 商業規則 / 法務風險 / 會動到 repo 外 Owner 的檔案或錢)→ 用本 template
- 不會(命名 / 門檻數字 / 目錄結構)→ 不要用。自己拍板,標 `[Owner 可否決]`(原則 8)

**浮上來 ≠ 停下來**:先把不依賴這個答案的部分做完,再送請求。

## 與原則 8 D-numbering 的分工

| 時點 | 機制 |
|---|---|
| Plan 階段(Step 1-2)的非關鍵決策 | plan file「Sensible Defaults」段,D1-DN 編號,Owner 可否決 |
| **執行中**(Step 3-6)浮現的真實取捨 | **本 template**,整理後送 Owner 拍板 |

兩者不重疊:D-numbering 是「我先做了,你可以推翻」;本 template 是「這題必須你拍板,
我把功課做完了」。

## Template(照抄修改)

```
# DECISION_REQUEST — <一句話問題標題>

## 1. 問題摘要

<一句話:要決定什麼、為什麼現在卡住。>

## 2. 已確認事實

- <事實 1,附證據:path:line / 命令輸出 / 文件出處>
- <事實 2>
- <事實 3>

## 3. 選項與影響

### 選項 A:<做法一句話>
- 影響:<對範圍 / 行為 / 使用者的影響>
- 成本:<工時 / 複雜度>
- 風險:<會壞什麼、機率>

### 選項 B:<做法一句話>
- 影響:
- 成本:
- 風險:

## 4. 推薦建議

**選項 <X>**——<理由一句話>。
```

## 紀律

- **事實與意見分開**:第 2 段只放可核實的事實(每條附證據);推薦放第 4 段,只推一個。
- **選項 2-4 個**:超過 4 個表示問題沒收斂,先自己收斂再送。
- **等待期間不停工**:送出後繼續做不依賴答案的部分;依賴答案的部分標記暫停點。
- 拍板結果照既有慣例記錄:影響 plan 的寫回 plan file;屬長期教訓的進
  `.claude/memory/LESSONS.md`。
